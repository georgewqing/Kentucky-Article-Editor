# 需求提案 · 文学写作辅助 Agent 能力升级

> 版本：v0.1（研究稿）
> 日期：2026-08-11
> 背景：基于真实长会话复盘（随笔 → 15 章长篇《艾尔德兰三部曲》 → 短篇《星尘邮局》 → 多轮测试），
> 提炼"作为文学写作辅助 agent 还缺什么能力"。

---

## 一、问题背景

当前 agent 的**单项能力**（写作、对白、思维导图、计划、连续性校验）已经稳定可用，
但作为"文学写作辅助"工具，存在结构性短板：**它擅长"写"，不擅长"记住自己写过什么"。**

体现在长篇创作中：

| 痛点 | 真实案例（艾尔德兰 15 章） |
|---|---|
| 道具下落丢失 | 「精灵之叶」ch03 交付后，直到全书终稿才想起没收尾 |
| 伏笔未埋先收 | 「黎的遗言」ch10 没埋设，ch11 直接让主角"记起"——逻辑断裂 |
| 角色设定漂移 | 塔林/瑟兰/蚀影的说话方式在 15 章里轻微漂移 |
| 环境细节失控 | 火堆亮度、在场角色、时间流逝写到后段会飘 |
| 长文记忆衰减 | 15 章后引用前几章细节，必须重新读文件 |

---

## 二、目标

让 agent 从"会写故事的引擎"升级为"**记得住自己故事的管理者**"：

1. 写作时**实时知道**哪些设定/道具/伏笔处于什么状态
2. 改动一处时**自动预警**对全书的连锁影响
3. 每一章的**风格、声线、环境**与开篇锚点保持一致

---

## 三、核心能力提案（P0）

### 提案 1：作品状态表（Story State Sheet）

**一句话**：每章自动登记"发生了什么事"，形成全书可查询的状态数据库。

**数据模型（每章自动提取）**：

```yaml
chapter: ch04
新增角色: [巴德罗]
出场角色: [塔林, 莫尔温, 巴德罗]
新增道具: [矮人之锤]
道具位置: {精灵之叶: 塔林, 北民之火: 英格, 陶罐: 塔林}
时间流逝: 3天
地点: [长草平原·旧驿站]
埋设伏笔: [铁砧宫暗火渗矿脉]
回收伏笔: []
角色状态: {英格: 带着灯, 瑟兰: 记忆裂痕}
```

**能力**：
- 写作时对 `道具位置`、`角色状态`、`时间` 做实时断言（"塔林此刻不该有矮人之锤"）
- 提供"作品状态一览"：当前谁拿着什么、谁在哪、过了多久
- 与 `continuity_check` 打通：状态表作为校验基准

**价值**：从"事后全文扫描"升级为"事前实时守卫"，是长篇的命门。

---

### 提案 2：伏笔台账（Foreshadow Ledger）

**一句话**：记录"何时埋、何时应回收、是否已回收"，未回收的定期提醒。

```yaml
伏笔: 谷民好运=灶火自燃
埋设: ch09 (沙语荒漠·南民老头)
应回收: ch13 之前
回收: ch13 (塔林献火性) ✅
---

伏笔: 精灵之叶
埋设: ch03 (精灵王交付)
应回收: 第三部
回收: ❌ 未回收 (终稿才补)
```

**能力**：
- 埋设时自动登记；正文出现回收迹象时提示"可标记回收"
- 完稿扫描：列出所有"已埋未收"伏笔 → 直接变成改稿清单

**价值**：长篇（三部曲/系列）的结构完整性保障。

---

### 提案 3：风格锚点（Voice Anchor）

**一句话**：开篇定调，之后每章对照，偏离即提醒。

**锚点数据（第一章生成）**：

```yaml
叙述人称: 第三人称限知 (POV1 塔林)
时态: 过去时为主
句式: 短句+留白, 偶用破折号
比喻密度: 中低, 乡土气息 (灶火像怕人的野猫)
词汇倾向: 日常口语, 少书面语
对白风格: 谷民=土味短句; 精灵=诗化长句; 蚀影=低沉鬼气
```

**能力**：
- 新章节写完后输出"风格偏差报告"（句式长度/比喻密度/用词 vs 锚点）
- 多 POV 作品：按角色切换锚点（塔林章 vs 蚀影章）

**价值**：决定作品有没有"个人味"，而非"AI 味"。

---

### 提案 4：角色声线库（Voice Bank）

**一句话**：角色卡之外，多一个"说话方式"数据层。

```yaml
阿澈:
  口头禅: [其实吧, 那个]
  句长: 短, 常吞吞吐吐
  语气词: [嗯, 唉]
  比喻来源: 邮局/信/日常物件
老苍:
  口头禅: [信到即忘, 莫问]
  句长: 长而玄
  语气词: [罢了]
  比喻来源: 星轨/记忆/三百年前的物件
```

**能力**：
- 写对白时自动对齐声线；多角色对话能自动区分归属
- 对白文件（.dialogue.csv）可直接引用声线做 emotion 建议

**价值**：对白"活"起来，角色不串味。

## 五、实现思路（供工具侧参考）

### 数据层
- 建议新增文件：`story_state.yaml`（状态表）+ `foreshadow.yaml`（伏笔台账）+ `voice_bank.yaml`（声线库）
- 与 `characters.csv`、`chapters/` 并列，随作品目录走

### 工具接口（设想）
- `update_story_state`：每章结束后自动提取更新（或写作时增量登记）
- `check_continuity`：升级为"状态表断言 + 伏笔回收检查 + 风格偏差报告"三合一
- `set_voice_anchor` / `compare_voice`：风格锚点管理
- 输出：结构化报告（severity/path/quote/suggestion），沿用现有 issues[] 风格

### 与现有功能的关系
- 依赖：`continuity_check`（已稳定）、`characters.csv`（已稳定）
- 不冲突：`.kmind`、`.dialogue.csv`、计划功能各自独立

## 六、优先级与里程碑

| 里程碑 | 内容 | 预估工作量 |
|---|---|---|
| M1 | 作品状态表（提案1）+ 伏笔台账（提案2） | 中 |
| M2 | 风格锚点（提案3）+ 角色声线库（提案4） | 中 |
| M3 | 场景状态机 + 版本历史（提案5/6） | 中高 |
| M4 | 素材库/读者模拟/译名/校验（提案7-10） | 渐进 |

**建议先做 M1**：状态表 + 伏笔台账，对长篇价值最大、实现最聚焦。

## 七、验收标准（草稿）

1. 写完 15 章长篇后，`作品状态一览` 能回答：谁拿着什么、谁在哪、过了多久、哪些伏笔未回收
2. 写作时引用"当前不该有的道具/角色" → 立即预警
3. 风格偏差报告能指出"ch12 的塔林说话不像塔林了"
4. 伏笔台账能生成"未回收伏笔"清单，一键转改稿任务

## 九、产品决策记录（v0.2 · 2026-08-11 批注后固化）

> 以下 Q1–Q4 来自工具侧批注，推荐方案已确认，作为实现约束写入。

### Q1 · 交付节奏 → M1 独立可上线，基线复验通过再进 M2

- **决策**：M1（状态表 + 伏笔台账）**必须可独立上线**，用真实长篇（如艾尔德兰/星尘邮局）压测通过后再开 M2。
- **约束**：M1 的 `story_state` 契约（yaml schema + toolApi 指纹）在 M1 **定死**，M3/M4 只增不改。
- **理由**：一口气做完会令状态表契约被 M3 scenes / M4 glossary 反复修改，toolApi 与测试基线碎裂。
- M3/M4 可并行设计，但**代码不合并进同一指纹**。

### Q2 · 状态与正文冲突 → 只警告，不设硬门禁

- **决策**：`continuity_check` 报出"塔林不该有矮人之锤"后，系统**只警告**（issues[] + 提示词要求先处理），**不接入 decideAutoApply**。
- **理由**：硬拦会激怒"我就是要写反转"的作者；文学创作中"违反当前状态"常是最高光时刻。
- **出口**：作者想写反转，用 `propose_upsert_story_state` **显式改表**，让作者意志通过工具表达。
- **补充（agent 立场）**：冲突可按 severity 分级——`warn`（道具位置漂移）/ `info`（轻微称呼不一致），作者可控噪音。

### Q3 · 忘记登记 → 软提醒 + 轻量 stale 警告（B + 轻量 C）

- **决策**：
  - B：写完正文后，若 `story_state` 缺该章记录，结果挂 `reviewHint` / 警告（软提醒）。
  - 轻量 C：`continuity_check` 在"焦点章无对应 chapter 记录"时给 **warn**（非 error），逼下一轮补登但不打断。
- **补充（agent 立场）**：**随笔/单篇豁免**——无 `chapters/` 目录或未启用状态表的工作区，不给 story_state_stale 警告，避免误伤轻量使用（本次会话的随笔就是例子）。

### Q4 · 工作区文件噪声 → 按需创建，禁止脚手架

- **决策**：`story_state.yaml` / `foreshadow.yaml` / `voice_*.yaml` / `glossary.yaml` 等记忆文件**按需创建**（第一次用相关工具才落盘）。
- **缺文件** = 空表 + `*_missing` info，**不提供"一键初始化全部记忆文件"**。
- **补充（agent 立场）**：记忆文件**默认随作品目录可见**（作者可直接改，符合"世界书"直觉）；`.kentucky/` 只放工具内部状态。

## 十、v0.2 变更记录

- 新增「九、产品决策记录」：固化 Q1–Q4 四条实现约束
- 提案 1 补充：状态表契约 M1 定死，M3/M4 只增不改
- 提案 2 补充：冲突只警告 + `propose_upsert_story_state` 显式改表出口
- 提案 3 补充：记忆文件按需创建、随笔/单篇豁免 stale 警告
- **Q5–Q9 决策已并入第九节（见下）**

### Q5 · 「启用状态表」精确判定 → 有文件 + 至少一章记录（B）

- **决策**：`story_state.yaml` 存在 **且 chapters 长度 ≥ 1** 才视为启用；启用后才有 stale 警告 / 软提醒。
- **排除 A**：文件存在即启用——agent 误 upsert 一次就永久"打开噪音"。
- **排除 C**：显式开关（enabled: true）对普通作者多一层概念负担。
- **兜底**：`*_missing` info 只在"用户显式要求 continuity 查 prop/timeline 但无表"时出现。

### Q6 · M1 schema 冻结边界 → M1 不预留，M3 增量加键（A）

- **决策**：M1 的 `story_state.yaml` 只含当前需要的键（不写 `scenes: []` 占位）；解析器**忽略未知键**；M3 增量加顶层键 + 可选 `current.sceneId`。
- **排除 C**：独立 `scene_state.yaml` 会造成两份 current，状态查询时"该看哪份"漂移。
- **约束**：M1 契约面最小，toolApi 指纹在 M1 定死后只增不改。

### Q7 · 写后软提醒挂在哪些写入上 → C 为主 + 偶尔 A 降级

- **决策**：默认**不污染每次 write 的 reviewHint**；stale 提醒靠 `continuity_check` 的 `story_state_stale`。
- **降级到 A**：仅当写入路径明显是章节文件且启用态时，可挂"考虑 upsert_story_state"的轻提示。
- **纪律**：System prompt 仍要求写章后 upsert；工具兜底、纪律兜认知。

### Q8 · compare_voice / 读者模拟 → M2 用 A（薄统计），M4 用 B（骨架）

- **决策（M2）**：主进程只做薄统计（句长、口头禅命中率）→ issues[]（severity/path/quote/suggestion，与 continuity 风格统一）；深度评价留给模型读结果后改稿。
- **决策（M4）**：reader_critique 工具几乎 passthrough——只返回 persona 清单 + 文件元数据 + 骨架路径，critique 由模型在对话里生成。
- **排除 C**：工具内嵌 LLM 做 critique——贵、难控、和现有 tool 循环叠床架屋，引入"工具内置另一个模型"的版本耦合。
- **原则**：**工具不装假智能**。规则能做的做统计，规则做不了的交给模型。

### Q9 · revisions/ 磁盘上限 → 默认 20 份，满则删最旧（环形）

- **决策**：默认最多 N=20 份快照。再 `create` 时删掉最旧一份再写入（FIFO），不拒建。结果带 `evicted[]`。
- **排除 B**：满则报错等作者手删——上限一到 Agent 大改前就拍不了，日常也没人去清隐藏目录。
- **补充**：N 值可配置（短篇 5 份、长篇 30 份），作者按项目规模调整。已有超过 N 的仓，下一次 create 会先删到 N-1 再写入，最终仍是 N 份。

### Q10 · stale 映射 focusPaths → A + B 混合，sourcePath 全空时降级 info

- **决策**：有任一 chapter 填了 sourcePath 才启用"路径级 stale"；chapters 全无 sourcePath → **不报路径 stale**，改报一条 `info` `story_state_unlinked`（建议补 sourcePath）。
- **可选参数**：`continuity_check` 支持 `chapterId` 作加速，不作唯一开关。
- **理由**：A 单独用会在 sourcePath 常空时吵；B 单独用会让 stale 形同虚设；混合 + 降级 info 兼顾两者。

### Q11 · 道具冲突断言 → A 为 M1 冻结，C 作可选增强，B 不进 M1

- **决策（M1 冻结）**：主进程**只做表内一致性**——章的 propsAt vs current.props、伏笔引用的道具是否在表内等；**不对正文做道具抽取**，正文矛盾交给模型读表后自行报/改。
- **可选增强（不挡 M1）**：工具接受 `assertions[]` 参数（agent 主动断言"此刻 X 应在 Y"），主进程只校验断言与表是否一致。
- **排除 B**：弱启发式在正文搜道具名 + 邻近窗口找持有者——误报率太高，会毁 continuity 信誉（ghost_character 误报教训）。
- **原则延续**：工具给校验、模型给判断；不装假智能。

### Q12 · foreshadow dueBy 触发 → A + 永远输出 unpaid 清单

- **决策**：仅当 dueBy 精确等于某 chapter.id 且已存在"排序更晚"的章（按 chapters 序/id 序）而仍 open 时，报 `foreshadow_overdue`。
- **永远输出** `foreshadow_unpaid`（open 清单），due 的解读交给模型。
- **排除 B**：自由文本 dueBy（"第三部"）不自动 overdue，模糊匹配太脆。
- **原则延续**：工具给事实（哪些还开着），模型给判断（该不该现在回收）。

### Q13 · restore_revision → 与其它 Agent 写入一样自动写盘

- **决策**：restore 立即写盘（无 Accept），与「始终自动写盘」同一条路；`applyProposalToDisk` / DocumentHub 同步脏缓冲。
- **排除 A**：一律 Accept——与 U13 取消 Accept 后的产品不一致，实测也已自动落盘。
- **排除 C**：静默丢弃未保存编辑仍不可接受；写盘后黄脏，用户可 Undo / SCM 丢弃。

### Q14 · glossary / materials 门禁 → glossary 同级 cast（A），materials 按 prose（C）

- **决策**：`glossary`（作者世界书，尺寸小、频率高）→ **始终 auto + 强制落盘**，与 cast 同级。
- **决策**：`materials/` → `materials/*.md` 当 **prose 门禁**（新建 auto、覆盖 Accept）；`materials/index.yaml` 当记忆类 auto。
- **理由**：materials 一旦长大篇即正文，避免"记忆类 auto"误伤大文件。

### Q15 · assertions[] 进 M1 冻结面 → 带可选参数（A）

- **决策**：M1 就暴露可选 `assertions[]`（空则忽略），**进冻结面**；以后只增字段不改语义。
- **理由**：参数可选、默认行为与"无 assertions"完全一致，冻结成本低，免得 M1.1 立刻 bump 契约。
- **补充约定**：将"空数组 / 未知字段一律忽略"写入 M1 契约说明——解析器对旧 agent 传的空 assertions 不误报，契约自带向后兼容。

### Q16 · L5 是否自动注入状态摘要 → 仅启用态注入极短摘要（A）

- **决策**：仅当启用态（文件存在 + chapters ≥ 1）时，注入极短 `current` 摘要（地点 / dayOffset / 道具数 / open 伏笔数），**有字符上限（建议 ~200）**。
- **摘要内容**：只注入**计数级数据**，不注入具体道具名、不注入伏笔内容——避免提前泄漏剧情、避免上下文膨胀。
- **定位**：摘要是"防忘"不是"替代读表"——关键操作前仍要求 `read_story_state` 读全量。
- **排除 C**：文件存在即注入（chapters=0）——与 Q5 启用判定对齐，避免随笔吃上下文。
