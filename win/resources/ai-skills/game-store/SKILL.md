# Steam与宣发文案

WHEN：商店页、短/长介绍、标签、胶囊一句、Devlog 提纲。不要在这里设计新玩法。

## 落盘

- `design/marketing/steam-store.md`：Steam **英文**短介绍、长介绍、标签候选、胶囊句
- 需要国内渠道时另节或 `design/marketing/store-zh.md`：**中文**，不要和英文混在同一段
- `design/marketing/devlog.md`：更新日志提纲

## 无活 GDD

若没有 `design/gdd.md`：仍可写，但必须在文首标明：

`状态：未对齐 GDD 的对话草稿`

并警告用户内容可能发明尚未设计的系统。有 GDD 之后必须对照，**禁止出现 GDD/系统文档里没有的功能**。

## 规则

- 先读 `design/gdd.md`（若有）和 `design/concept.md`。
- 短介绍像货架：谁、做什么、为何现在买。长介绍可列 3–5 条支柱，不要攻略。
- 标签必须是玩家能在商店理解的词，不要内部策划黑话。

## 禁止

- 用商店文案倒逼新系统进 GDD（应先改 GDD）
- 中英混写同一段落
